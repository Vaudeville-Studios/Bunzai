## Required concurrency and authority refinements

Independent plan review identified these load-bearing contracts; implement them before wiring production orchestration:

- Persist a `committing` phase with the exact frozen reviewed body and stable card ID. Reject edits, discard, start-over and competing save while it exists. Creation and the StateStore receipt are separate writes; preserve recovery evidence across either failure. Recovery can finish the same exact commit or report a collision; it cannot abandon an uncertain successful write. Test crashes immediately before/after create, receipt failure, and competing discard/save.
- Persist manual field ownership, including deliberately empty values. All later model responses must exclude manually owned fields unless the person explicitly releases that ownership. Rejecting only the in-flight revision is insufficient to protect against future generations.
- Persist pending operation identity and a bounded expiry. Reload observes an operation still owned by a live runtime, rather than declaring another client's operation interrupted. Retry is explicit after stopped/failed/expired/crashed ownership; it invalidates old tokens. Define the scoped runtime/controller owner shared by handlers for the same open library, with bounded cleanup. Test two clients, reload during a live call, Stop, crash, expiry and late response. Do not let GET/reload silently spend provider calls.
- Approved remote handlers have no host `LibraryHandle`. Resolve state through the existing `libraryStateFor(store.studioPath())` path used by scene routes, or inject an equivalent narrow feature service. Do not broaden remote library-management authority. Prove actual approved remote-handler construction, not merely a mocked host route, with authentication and cross-origin rejection intact.
- Static Pocket/browser mode shares the AppContext type. Implement only its supported behavior or an explicit unavailable state consistent with its provider support; never fake a successful interview or silently use an unrelated provider. Keep desktop/approved-device behavior complete.
- Composition refinement approved after source review: include narrow `src/ui/server-start.ts` wiring, analogous to sharedExtensionOwner, to pass one Table Read route owner to trusted and paired remote handlers. Its WeakMap is keyed by the actual StateStore and owns bounded active-operation controllers; only the trusted owning handler closes it. Abort and await tracked work before storage teardown. No remote LibraryHandle or hidden core singleton is introduced.
- Recovery must be usable without inference: provide an explicit no-model Review current draft transition. Preserve known fields, surface missing ones, invalidate/abort pending generation, and require a separate Save before creating a character. A failed or removed provider must not trap a retained draft behind another model request.
- A positively verified different/retired-ID collision is distinct from an uncertain commit outcome. Retain the draft and expose a safe explicit conflict/review recovery so the user can preserve or discard it and start again; do not permanently lock the only interview slot. Keep the frozen committing phase for uncertain create/receipt failures, and never automatically rename, overwrite or resurrect.
- Narrow security-helper integration approved: export/rename the existing foreign-site predicate in `src/ui/server-security.ts` as `refuseForeignSite`, preserving all existing gates' GET-only caller policy. - Source review refinement: Rapid Fire expiry stops accepting choices, and the final deck choice is also a persisted local answer without inference. A timer, reload, poll or completed deck never starts synthesis. The creator explicitly chooses Review current draft (no model) or Finish with interviewer (model). This replaces automatic synthesis wording and prevents repeated paid calls after failed/stopped finish or a new mount.
- Shutdown scope is precise: abort/deadline-race inference so a provider ignoring cancellation cannot hold the feature task; preserve the existing library's safe wait for pending storage operations. `database.idle`/`exclusive` can wait for other trusted jobs, so universal bounded storage shutdown is not claimed. Never race away from an uncertain mutation and close storage while it can still commit. Keep durable committing evidence and test that close joins an in-flight save before reporting completion. Global database scheduling/cancellation redesign is out of scope.
- Final UI lifecycle requirements: keep unsubmitted setup, one answer and one open field edit in a bounded in-memory app draft owner keyed by the existing PieceStore lifetime; no plaintext browser persistence or server write per keystroke. Room switches retain scratch text, while lock/restore clears the old lifetime. Include all unsent text in unload protection. Scope accepted server views and in-flight responses to that same lifetime before comparing document revisions, so a restored lower revision can replace the old library view and late old responses cannot cross the boundary.
