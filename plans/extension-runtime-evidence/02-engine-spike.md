# WP2 QuickJS engine and packaging spike

Status: QuickJS engine, Bun Worker, sandbox-origin frame/worker/WASM asset wiring, real Chrome adapter fixture, generated Pages browser path, compiled Terminal guest proof, and final combined Windows Desktop artifact have been exercised. The final Desktop binary loads WebView2 with automatic DLL extraction, displays the embedded application icon, and activates a guest extension. Native file-picker and offline behavior remain unverified.

## Candidate and license

- `quickjs-emscripten-core@0.32.0` plus `@jitl/quickjs-wasmfile-release-sync@0.32.0`.
- Release-sync is the single selected variant; it avoids pulling debug and Asyncify WASM variants. Upstream describes it as ESM for browser and Node, with a separate WASM file. Its MIT license and both direct packages' MIT licenses passed `bun run license:audit`. `@jitl/quickjs-ffi-types@0.32.0` is the sole transitive runtime package and is MIT.
- Installed package unpacked sizes: core 794,874 bytes, variant 649,548 bytes, FFI types 79,995 bytes; selected variant's built `dist` files total 643,012 bytes, of which `emscripten-module.wasm` is 503,134 bytes. The packaged Windows proof artifact was measured separately at 426,126,336 bytes; that executable size includes the Bun runtime and full application, not only the extension engine.
- Upstream API exposes `setMemoryLimit`, `setMaxStackSize`, `setInterruptHandler`, module-loader controls, and the WASM memory handle. Guest module loading is never configured. Guest code is passed as a string into QuickJS `evalCode`; no Bun/browser native guest eval or imports are used.

## Implemented boundary and measurements

- The engine is [`src/sandbox/javascript/engine.ts`](../../src/sandbox/javascript/engine.ts), with a fresh runtime/context per job. It installs only a bounded request callback and capped log callback. Host calls use the existing shared `ExtensionWireRequest` / `ExtensionWireReply` envelope and value decoder from `src/extensions/contracts`. `bunzai.extension.define({commands, events})` accepts only manifest-declared IDs once per job; initialization cannot invoke capabilities; the runtime invokes the requested handler with the shared `ExtensionInvocation` value.
- Limits: QuickJS heap 16 MiB, VM stack 512 KiB, configured WASM `WebAssembly.Memory` maximum 128 MiB (2048 pages), cumulative guest execution 2,000 ms, active VM lifecycle 10,000 ms, absolute worker deadline 300,000 ms, source 1 MiB, 32 outstanding host calls, and 100 pending-job pump budget. Caller overrides are clamped at release ceilings.
- Measured WASM memory for the tested guest allocating 50,000 small objects remained 16,777,216 bytes before and after the run. The memory is created with an explicit 2048-page maximum, so WASM growth beyond 128 MiB is rejected by the WebAssembly memory contract. QuickJS's own allocation budget and the WASM linear-memory budget are separate controls.
- [`src/sandbox/javascript/run-in-worker.ts`](../../src/sandbox/javascript/run-in-worker.ts) is the terminable host wrapper; [`worker.ts`](../../src/sandbox/javascript/worker.ts) imports the engine and relays only validated value requests/replies. Desktop compiled mode uses Bun's literal worker entrypoint and receives inline packaged WASM bytes; browser mode uses the trusted sandbox-frame path. Tests exercise a real Bun Worker, denied operation rejection, out-of-order asynchronous replies, sync-loop interruption, memory-pressure failure, no fetch/document/process/Bun/require/importScripts globals, module import denial, source cap, serialized bridge-argument byte cap before host JSON parsing, UTF-8-bounded guest logs, cancellation and ignoring late replies.
- Browser probing confirmed that Chrome refuses a cross-origin module `Worker` even when the script fetch succeeds with CORS. The browser adapter therefore creates the trusted `extension-frame.html` on the distinct sandbox origin; that frame owns the same-origin terminable QuickJS `Worker`. Frame/parent messages require the exact `contentWindow`, origins, version, nonce, strict envelope keys, and bounded shared wire schemas. The iframe CSP names the exact UI `frame-ancestors`, disallows all unrelated resources, and permits WASM compilation only via `'wasm-unsafe-eval'` in `script-src`. This is a plan adaptation based on actual browser behavior; no UI-origin worker/native-eval downgrade exists.
- Isolated-origin routes are `/sandbox/extension-frame.html`, `/sandbox/extension-frame.js`, `/sandbox/extension-worker.js`, and `/sandbox/quickjs.wasm`; desktop build output bakes frame, worker, and WASM bytes into `PackagedAssets`. The static Pages Browser path uses the opaque frame adapter and its generated worker/WASM bundle.
